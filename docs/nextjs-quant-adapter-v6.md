# nextjs-quant 适配层需求 v6：笔内K线不得超出端点（可配置，在 api v9 之上）

> 需求方：`D:\github\nextjs-quant`。起草：2026-10-01，基于 `cf0159c`（api v9）。
> 用户反馈：**一笔的形成过程中，会出现中间某根K线的高／低点超出这笔两个端点的情况**。用户希望这种行为可以配置。
> 以 108 课原文为准。先核实原文，结论登记进 `chan-ambiguity-decisions.md`。

## 1. 现状

`core/morphology.cpp`：

- `ValidStroke(a, b, c)` 只检查两端：`SpanEnough`（跨度）、`PriceProgress`（向上笔终点顶高于起点底分型K线高点，向下对称）、`Nested`（czsc 笔两端区间不互相包含）。分型笔只检查顶高于底。
- **不检查笔区间 (a.index, b.index) 内的原始K线**。因此可能出现：
  - 向上笔：中间某根K线的最低价 < 起点底的最低价，或最高价 > 终点顶的最高价；
  - 向下笔：中间某根K线的最高价 > 起点顶的最高价，或最低价 < 终点底的最低价。
- 产生的途径包括：同型分型因 `ValidStroke` 不达标被忽略（`StrokeStream::Add` 的 `return -1`），`RefineOne` 只在窗口内细化，包含处理吞掉的极值，以及十位 = 1（允许次高次低）本身。

## 2. 需求

### R1 口径核实（先做）

1. 原文（第62/65/69/77/79课等正文）是否要求一笔的顶是该笔区间的最高点、底是最低点？若有，请引用；若无，请说明这是社区口径。
2. 判定用原始K线还是包含处理后的K线？端点K线自身是否计入？价格相等算不算超出（建议相等不算超出，与既有“等于不算新高/新低”一致）？
3. 与十位 = 1（允许次高次低收笔）的关系：两者语义冲突。请选定：
   - (a) 组合非法，`czsc_config_valid` 返回 0；
   - (b) 新约束优先，十位失效；
   - (c) 其他方案。需求方倾向 (a)。

### R2 新增配置位：笔内极值约束（百万位）

| 百万位 | 名称 | 口径 |
|---|---|---|
| 0 | 允许超出（默认，与 v9 一致） | 现行规则 |
| 1 | 不得超出 | 一笔区间内（不含两端，或按 R1-2 的结论）任何K线的最高价不得高于该笔的顶，最低价不得低于该笔的底 |

**违反约束时如何处理**，请按原文与工程可行性选定并登记：

- (i) **改端点**：把端点移到区间内真实极值所在的K线。前提是那里也构成同型分型，且与前后端点仍满足 `ValidStroke`；不满足时退回 (ii)。
- (ii) **不成笔**：这对分型不成笔，继续等待；已成笔的前端点按同型延伸规则更新。
- (iii) 其他方案。

需求方倾向：优先 (i)，做不到时 (ii)。并请说明：

- 对线段、中枢、买卖点、递归层是否只是“输入的笔不同”而自然传递，有没有额外的地方需要改；
- 因果性和定型：约束需要看到区间内的全部K线，最后一笔未定型时怎么处理，会不会导致已定型的端点被改写；
- 对五种笔算法是否都适用（分型笔不设跨度，是否同样适用）。
