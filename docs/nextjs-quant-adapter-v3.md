# nextjs-quant 适配层需求 v3：缠论结构指标可配置（在 api v6 之上）

> 需求方：`D:\github\nextjs-quant`。起草：2026-09-30，基于 `98fb604`（api v6，中枢框只画最初三笔／三段）。
> 目标：K线图上的“缠论结构”指标允许用户像 TradingView 缠论指标（ChanLun Pro、缠论++ 等）那样切换笔、收笔、线段、中枢口径。
> 口径以 108 课原文为准；原文没有的口径（如 4K 笔）必须在 `chan-ambiguity-decisions.md` 登记为“非原文/社区口径”，不得冒充原文。

## 1. 现状

| 维度 | DLL 已支持（`core/config.h`） | nextjs-quant 现在的用法 |
|---|---|---|
| 笔 | 个位 `0` 严格（老笔）/ `1` 新笔 / `2` czsc 笔 | 固定 `0` |
| 收笔端点 | 十位 `0` 极值点 / `1` 允许次高次低 | 固定 `0` |
| 中枢构件 | 百位 `0` 笔中枢 / `1` 线段中枢 | 两套 family：`0` 和 `1100` |
| 线段 | 千位 `0` 启发式 / `1` 特征序列 | 同上 |

问题：
1. nextjs-quant 类型里写死了 `config: 0 | 1100`（23 处），图表不能换口径；这一处由我方改。
2. TradingView 常见选项里，DLL 缺 **4K 笔**、**分型笔**、**1+1 终结线段**。
3. `Config::Decode` 只接受当前各位的取值范围，前端无法知道哪些码合法、各位代表什么，只能在 TS 侧再抄一份，容易漂移。

参考 TradingView ChanLun Pro 的设置项：笔算法（老笔 / 新笔 / 4K / 分型笔）、线段算法（特征序列 / 1+1 终结）、允许次高次低端点（默认不允许）、允许中枢扩张、买卖点级别切换、分析K线数量上限。

## 2. 需求

### R1 补齐笔算法（个位）

| 码 | 名称 | 口径 |
|---|---|---|
| 0 | 老笔（严格） | 已有 |
| 1 | 新笔 | 已有 |
| 2 | czsc 笔 | 已有 |
| 3 | 4K 笔 | 社区口径（需求方已定）：顶底两个分型极值K线之间按**原始K线**计数，含两端共 ≥4 根，即极值K线下标差 ≥3；两分型不得共用K线，不要求合并后有独立K线 |
| 4 | 分型笔 | 相邻的顶底分型直接成笔，不设最小K线数量（仍须顶高于底、顶底交替） |

要求：
- 3、4 在决策表里标注“非原文口径，第62/77课原文为老笔／新笔”，并写明与 0/1 的差别。
- golden 测试为每种笔各加一段 SSE 回归，端点逐行固定。

### R2 补齐线段算法（千位）

| 码 | 名称 | 说明 |
|---|---|---|
| 0 | 启发式 | 已有 |
| 1 | 特征序列 | 已有（第67/71课） |
| 2 | 1+1 终结 | 请按原文判断：它是特征序列的某种特例，还是社区简化；登记后实现。若原文不支持，也可以明确拒绝，回写结论即可 |

### R3 中枢扩张开关（新增万位，可选）

万位 `0` 按第20课正常处理扩展（默认，与现状一致）/ `1` 不合并扩展，只保留同级别中枢。
**只影响结构显示**，关闭时买卖点照原样计算还是跟着变，请给出结论。如果关闭扩展会让第20课中心定理二的信号失去定义，那就只作为显示口径，并在 README 中注明。

### R4 配置自描述（api v7）

在 `czsc_api.h` 新增：

```c
/* 返回 1 表示 config 合法（能被 Config::Decode 解析），否则返回 0 */
int32_t czsc_config_valid(int32_t config);

/* 描述每一位（维度）及其取值，供前端生成设置面板；返回写入条数 */
typedef struct czsc_config_option
{
  uint32_t size;
  int32_t place;        /* 1 个位 / 10 十位 / 100 / 1000 / 10000 */
  int32_t value;        /* 该位取值 */
  int32_t isDefault;    /* 1 = 默认值 */
  int32_t original;     /* 1 = 108 课原文口径，0 = 社区/非原文口径 */
  char key[32];         /* 稳定英文键，如 "stroke.new"、"segment.feature" */
  char label[32];       /* UTF-8 中文名，如 "新笔" */
  char lessons[32];     /* 课文编号，如 "62/77"，非原文为空 */
} czsc_config_option;
int32_t czsc_config_options(czsc_config_option *out, int32_t capacity);
```

nextjs-quant 以这张表为唯一来源生成设置面板和校验，不在 TS 里重复写口径。`czsc_build_commit` 照旧用于缓存隔离。

### R5 任意配置码的结构化快照

确认 `czsc_build` 对任意合法配置码都能完整输出端点、中枢（含 v6 的 `established`）、走势、买卖点和递归表，不只是 `0` 和 `1100` 这两个。
在 `test_api.cpp` 里遍历所有合法码，对 SSE 做一次冒烟测试：不崩溃、端点顶底交替、中枢 `zd<zg`，且 `firstPivot+3` 不越界（`98fb604` 画框时依赖这一点）。

### R6 不做的事

- 不改默认值：`0` / `1100` 的输出必须与 v6 逐位一致（golden 不变）。
- 画框范围（最初三笔 vs 含延伸）属于显示口径，nextjs-quant 已经能拿到 `end` 和 `firstPivot+3`，自己切换即可，DLL 不必加开关。
- 颜色、线宽、K线数量上限都属于前端，DLL 不管。

## 3. nextjs-quant 侧配合（我方实现，列出来供对齐）

1. **类型放开**：`config: 0 | 1100` 改为 `number`。研究、监控、信号台账**继续锁定** `0` / `1100`，以保证回测可复现；只有图表读取用户配置。
2. **设置面板**：参照 TradingView 指标的“输入”页，分组如下：
   - 笔：算法（下拉，读 R4 选项表，非原文口径加“社区”标记）、端点（极值点 / 允许次高次低）
   - 线段：算法
   - 中枢：构件级别（笔 / 线段，可同时显示两套）、画框范围（最初三笔 / 含延伸）、扩张（R3）
   - 买卖点：显示本级别 / 次级别、事后买卖点开关
   - 样式：颜色、透明度
3. **持久化**：配置按用户保存（和画线一样跨周期共享），缓存键 = `symbol + period + config + czsc_build_commit`。
4. **校验**：保存前调用 `czsc_config_valid`；非法码回退到默认值并提示。

### 步骤3：口径结论

### R2：拒绝新增千位2（1+1终结）

依据[第67课](https://github.com/stockServ/chzhshch-108-plus/blob/main/108/0614-486e105c01000c16-067.md)与[第71课](https://github.com/stockServ/chzhshch-108-plus/blob/main/108/0639-486e105c01000c8i-071.md)正文：线段至少三笔且前三笔重叠；无缺口由特征序列分型结束，有缺口需反向特征序列分型确认。
第71课首笔破坏后反向三笔突破第一笔终点，是有条件的特例；若先破第一笔起点，旧线段继续。不能将该特例替换所有缺口、包含与延续判定。
“1+1终结”这个名称没有给出足以编码的社区规则，也未提供证明它等价于上述两种情况的依据。因此不开放千位2，不把一个推测的简化冒充原文算法。若未来需求方给出完整社区判据，可作为 `original=0` 的新口径另行验收。

### R3：仅作显示口径，不新增可选万位

依据[第20课正文](https://github.com/stockServ/chzhshch-108-plus/blob/main/108/0424-486e105c010007zw-020.md)：两个同级中枢波动区间重叠对应高级别中枢；中心定理二据GG/DD关系区分趋势与扩张。关闭这个计算会把扩张误判成趋势，进而改变走势和一类点的前提。
结论：关闭扩张显示时，买卖点、事件、走势关系仍按完整结构计算。扩张与同一中枢的延伸是不同概念，关闭扩张显示不截断同级中枢的延伸。
当前 `czsc_centers` 已保留各同级中枢，并不将相邻扩张中枢合成一行；高层结构另在递归表。因此前端“仅同级”可只绘制 `czsc_centers`（递归节点只取level=0），不绘制递归中枢表；保持信号和事件表不变即可。
拒绝改变第20课计算规则；可选万位显示开关不加在DLL配置中，以免消费者误解它改变结构。万位仍必须为0，10000与千位2都非法，自描述表无这些选项。前端显示开关属于社区/非原文显示口径，不应打上原文标记。
