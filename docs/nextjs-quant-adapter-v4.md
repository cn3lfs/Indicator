# nextjs-quant 适配层需求 v4：线段分界点可配置（在 api v7 之上）

> 需求方：`D:\github\nextjs-quant`。起草：2026-09-30，基于 `a271e5c`（api v7）。
> 背景：用户希望线段分界点可选：极值笔（现状）、合并后特征元素的**起始原始笔**、或**最后原始笔**。
> 口径以 108 课原文为准。第67课原文：线段结束于特征序列分型的顶／底，即极值处。新口径不是原文，登记为 `original=0`。

## 1. 现状

`core/morphology.cpp`：

- `MakeElement`：特征元素 = 一根反向笔，`inner` 为该笔起点端点，`outer` 为终点端点；`highAt`／`lowAt` 指向该笔较高／较低的端点。
- `FeatureSequence::Settle`：相邻元素有包含关系时合并。向上取高高，并且 `cur.high >= last.high` 时 `highAt = cur.highAt`（向下对称）；`last.outer` 顺延到被并入的元素。
- `FindSegmentEnd`：找到特征分型后，终点 `end = dir > 0 ? s[i].highAt : s[i].lowAt`。

结果：终点是合并元素中**极值所在的原始笔**的端点；价格相同时取**后一笔**。

## 2. 需求

### R1 新增配置位：线段分界点（万位）

| 万位 | 名称 | 口径 |
|---|---|---|
| 0 | 极值笔（默认，与现状一致） | 终点为合并元素中极值所在原始笔的端点（第67课） |
| 1 | 合并起始笔（社区口径） | 终点为分型顶（底）那个合并元素中**第一根原始特征笔**的起点端点（即该元素合并前的 `inner`）。向上线段取顶，向下线段取底 |
| 2 | 合并最后笔（社区口径） | 终点为该合并元素中**最后一根原始特征笔**的起点端点（最后并入元素的 `inner`）。与 0 的区别：0 跟随极值所在的笔，极值在前面的笔时两者不同；未发生包含时 0/1/2 三者相同 |

- 只在千位 = 1（特征序列）时有意义。千位 = 0（启发式）且万位 ≠ 0，`czsc_config_valid` 返回 0。
- 默认 0：配置 0 / 1100 与 v7 逐字节一致，golden 不变。
- `czsc_config_options` 增加 `place=10000` 的三行，key 为 `segmentEnd.extreme`（original=1，lessons "67"）、`segmentEnd.first`、`segmentEnd.last`（后两者 original=0）。

实现提示：给 `Element` 增加 `firstInner`（保持为第一个元素的 `inner`，不随合并更新）和 `lastInner`（每次合并时更新为被并入元素的 `inner`），由 `FindSegmentEnd` 按配置选择 `highAt/lowAt`、`firstInner` 或 `lastInner`。**不要改动**合并本身的高低取值，特征分型判定仍用合并后的区间。

### R2 必须先给结论：与第71课“起点被破，旧线段延续”的冲突

万位 = 1 或 2 时，终点端点可能不是极值（合并组后面还有更高的顶／更低的底）。这会带来两个问题：

1. 下一段刚开始，这个更高的顶就会让 `StartBreak` 判定“起点被破，旧线段延续”，终点被顺延回极值，选项实际上失效。
2. 有缺口的情况下，“原线段再创新极值之前出现反向分型”这一检查以 `p[end]` 为基准；改成非极值端点后，基准怎么取？

请按原文分析后在 `chan-ambiguity-decisions.md` 登记，并选定一种（或给出更好的方案）：

- (a) `StartBreak` 和新极值检查的基准仍然用合并元素的**极值端点**，只把**输出的分界端点**换成合并起始笔／合并最后笔。结构判定与默认口径完全一致，只是端点位置不同。
- (b) 分界端点和所有判定基准都换成所选的合并起始笔／合并最后笔，并对合并组内的端点豁免 `StartBreak`。
- (c) 认为原文不支持，拒绝 R1，回写理由。

需求方倾向 (a)：线段的划分（哪几笔属于哪一段）保持原文判定，只改分界点画在哪。但 (a) 下，线段端点价格不再是该段的极值，下游需要明确的有：

- 线段中枢 ZG/ZD、线段级背驰的力度区间（第24/37课 a/b/c 段）、买卖点的失效价，是用分界端点还是用该段真实极值？请逐项给出结论。
- `czsc_pivot.price` 仍然是分界端点那根K线的高／低。另外请在 `czsc_pivot` 末尾追加 `extremeIndex`（该段真实极值K线），默认口径下它等于 `index`。这会改变结构体布局，所以需要 api v8。

## 答复

### R2：方案与下游口径

## v4：线段分界点显示（R2，社区/非原文口径）

选择方案 **(a)**：核心线段端点始终为真实极值，另记录特征分型中间合并元素的首笔/末笔起点，仅适配层切换显示端点。万位1/2均 `original=0`。
依据[第67课正文](https://github.com/stockServ/chzhshch-108-plus/blob/main/108/0614-486e105c01000c16-067.md)：无缺口在分型极值结束；有缺口须从该极值开始的反向特征序列分型确认。
依据[第71课正文](https://github.com/stockServ/chzhshch-108-plus/blob/main/108/0639-486e105c01000c8i-071.md)：先破第一笔起点时旧线段延续。以较低顶/较高底代替真实极值，会让合并组内原有极值被误认成新突破。
因此 `StartBreak` 的起点、遍历范围、下一段扫描起点、有缺口反向扫描起点与“再创新极值”比较均保持默认极值，不对合并组作豁免；合并高低值、价格相等取后一极值笔的规则不变。方案(b)会改变原文划分与信号定义，拒绝采用。

| 下游量 | 采用的口径 | 显示后果 |
|---|---|---|
| 线段中枢 ZG/ZD、GG/DD、start/end、established | 真实极值端点及默认三段范围（第17/20课） | 中枢数值/时间不随显示分界移动；不可用显示端点重算框值 |
| 背驰价差/速度、MACD区间、a/b/c及递归走势 | 真实极值价格与K线区间（第24/37课） | 数值与万位0完全相同 |
| 买卖点位置、失效价、出现/撤销事件 | 真实极值及默认结构计算 | 信号index不一定等于所引用端点的显示index；同一pivot表序号对应同一分析端点 |
| czsc_pivot.index / price | 选定首笔/末笔起点K线及该K线高/低 | 只用于画线，首个端点或无合并元素时回落真实极值 |
| czsc_pivot.extremeIndex / fractalAt / confirmedAt | 真实极值K线、极值分型成立时刻、整个显示映射定型时刻 | 万位0或笔级 extremeIndex=index；中枢established仍对应真实分型 |

核心Snapshot保持分析端点；适配层与TDX端点投影共享显示下标选择。合并组范围与极值都纳入读取视界/检查点，首末位置变动也须报告dirty，已定型映射不回改。
这些是社区显示规则，不是第67课原文线段的新定义。消费者须用 `extremeIndex` 对齐买卖点、跨级别映射与分析时间，不能把显示折线当成分析输入。
