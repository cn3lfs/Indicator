> 2026-09-27，基于 `dev` 上 api v2（P0 + P1 已交付）。
> 更新：按 §5 建议已交付 v3（走势完成证据 + 高级别背驰段的低级别端点映射）与 v4（`CZSC_FLAG_HIGHER` 递归走势节点）；日期锚维持不进 DLL。

## 1. 趋势对象与完成证据

- 成员中枢：走势表的 `firstCenter..lastCenter` 已是连续区间，直接给出即可（不需新表）。
- 完成证据（第17课“走势终完美”：走势完成的标志是转为另一走势类型）可在引擎里当下给出：
  - `completedBy`：终结该趋势的一类买卖点（信号表下标）——第29课：趋势背驰导致转折；
  - `successor`：其后的走势（走势表下标）与 `successorEstablishedAt`：后继走势的首个中枢成立的K线；
  - `connection`：两走势的连接端点（端点表下标）。
- 这些都能沿用现有“定型时刻”机制保证因果。建议作为 v3 追加到 `czsc_movement` 末尾。

## 2. 高级别候选

- 现在已能得到：`config=1100` 快照中的一类信号（带趋势、中枢、背驰段），以及 `czsc_nested_build(low=0, high=1100)` 的配对。
- 缺口：高级别背驰段 b/c 的起止端点是线段端点，调用方想要“对应的笔端点”时，需要把线段端点映射回笔端点表。
  线段端点必是笔端点的子集（第67课），按K线身份即可映射，建议在区间套表或独立映射表中给出，工作量小。
- 注意：上证日线本身在线段级只有“扩展”关系，没有线段级趋势，因此没有线段级一类（第20课中心定理二的正常结果，非缺陷）。

## 3. 递归节点

- 第17课：某级别中枢 = 至少三个连续次级别**走势类型**的重叠。要把“以某级别中枢为元素的上一级走势”做对，构件必须是次级别走势类型，
  其端点是走势之间的连接点，而现有走势表的起止是首末中枢的起止（不含连接段）。
- 方案：在引擎中为每个已完成走势补“起止连接端点”，把已完成走势序列作为下一层 `CenterStream` 的输入（构件需按起止价定方向；
  盘整的方向按其起止端点），递归至不能再形成中枢为止。多义性按第33课取一种满足结合律的确定分解，并登记口径。
- 因果与定型：沿用读取视界与定型时刻，递归层的对象定型必晚于其构件定型。
- 字段可覆盖需求所列 `level/start/end/centerStart/centerEnd/established/connection/completed/successor/children`。

## 4. 日期锚：交给调用方重采样是否丢失原文语义

**结论：不丢原文语义，建议 DLL 不再处理日期锚。** 理由：

- 原文的“级别”是递归定义的（第17课：次级别走势类型 → 本级别中枢），与K线周期无必然关系；第63课明言“什么级别的图和什么级别的中枢没有任何必然关系……级别的图就如同显微镜”。
  周线、月线只是换一台显微镜看同一走势，在重采样后的序列上做一遍完整分析，本身就是合乎原文的分析。
- 真正的“高级别”应由同一序列内的递归得到（§3），它不需要日期。旧实现把“周期锚”和“递归级别”混在一张表里，拆开后两者都更清楚。

但重采样方案会**丢掉三样工程性质**，必须由调用方承担：

1. **未完成周期的因果性**：本周/本月尚未收盘时，重采样得到的最后一根周K线的高低点还会变。DLL 的定型与事件只对“已给出的K线”因果；
   调用方要么只喂已完成周期，要么把最后一根当作临时K线、每个交易日重建快照，并只信任 `confirmedAt` 不晚于倒数第二根的对象。
2. **下标换算**：周/月快照中的K线下标属于周/月序列；映射回日线时，应把事件发生在“该周期最后一个交易日收盘后”，否则会引入未来函数。
3. **跨周期区间套**：`czsc_nested_build` 要求两个快照来自同一数据；日线与周线快照不满足，DLL 无法配对，调用方需按日期区间自行关联
   （日线信号落在周线背驰段的日期范围内），并同样遵守第 1 条。
4. （次要）周K线合并了周内高低点的先后顺序，包含处理与分型只能按周K线本身判断——这属于“换显微镜”的正常结果，不是缺陷。

## 5. 建议的接入顺序

1. v3：走势完成证据（§1）+ 高级别候选的笔端点映射（§2），工作量小，可先交付；
2. v4：单序列递归节点（§3）；
3. 日期锚不进 DLL：nextjs-quant 自行重采样周/月，按 §4 的三条约束使用。
